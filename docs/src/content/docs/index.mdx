**house lights** is an Amsterdam arts event tracker. It scrapes the programme pages of 25+ venues — theatre, dance, music, performance — and brings everything into one searchable, filterable feed with watchlist, calendar sync, and friend activity.

This documentation covers the full technical internals: the scraping pipeline, database schema, frontend architecture, and deployment setup. It's written for contributors and for anyone curious about how the project is built.

## The short version

1. Python scrapers run on a schedule via GitHub Actions and write shows to Supabase
2. The Astro frontend (SSR on Vercel) queries Supabase directly — no separate API server
3. Row-level security on Supabase means the frontend can safely use anon/user keys
4. Social features (follow, notifications, feed) are built on top of the `friendship` and `notification` tables with Supabase Realtime for live bell updates
5. `dev` → `main` is the branching model; PRs require Bearer security scans to pass
